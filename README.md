# meisho-scanner（名証コンテスト用 夜の好材料スキャナー）

名証の学生向け株式投資コンテストのために、**引け後（15:30以降）に出た名証上場銘柄の適時開示**を集めて分類し、スマホで見られる1ページにまとめるツールです。売買やコンテストサイトへのログインは一切しません。

- 仕様：[SPEC.md](SPEC.md)
- 公開ページ：GitHub Pages を設定すると `https://<ユーザー名>.github.io/meisho-scanner/` で見られます

## 自動実行
取引所の営業日の日本時間 **16:10・17:10・18:40・20:40・20:55・22:40**（夜）と **6:20・7:05**（朝レポート）にスキャンします。20:55 は、21:15 のAIアナリストの前に入力を新しくするための回です。
- **起動するのは Cloudflare Worker の定時起動（Cron Triggers）**です。5分ごとに動き、上の時刻のときだけ GitHub の scan を起動します（repository_dispatch）。GitHub Actions の時刻指定（schedule）は数時間遅れることがあり（2026-11-04 は16:10〜20:40が1回も動かなかった）、予備として残しています。同じタームで何回動いても、LINEやAIの起動は重複しません。
- 22:30 の「AIの判断が届いたかの確認」（ai-watch）も Cloudflare から起動します。届いていなければ、AIをもう一度起動してLINEで知らせます。
- 祝日・年末年始は実行しません。土日は最初から予定に入れていません。
- GitHubの都合で、数分〜数十分遅れることがあります。
- すぐに実行したいときは、GitHub の **Actions** タブ →「scan」→「Run workflow」を押します（手動実行）。

## ページの見方
最上部の **「今夜の結論」**（朝は「今朝の結論」）に、今夜の行動を3行以内でまとめています（買い候補1位・保有中の売り推奨・名証単独銘柄の購入状況）。保有銘柄に警告があれば、その上に赤い枠が出ます。

そのほかの欄：
- **ストップ高・ストップ安**：名証の日報とJPXの制限値幅表で判定。張り付き（最終気配がストップ高）が最上位。「現実では買えないがコンテストでは買える」
- **新規上場**：名証に新しく上場する銘柄（上場日の16:30から買える）。上場日の最終気配・初値の有無・単独かどうか
- **保有管理**：評価額・損益・10位ラインとの差・今タームの残り枠・入れ替え案
- **朝レポート**（6:20・7:05）：米国株・ドル円・日経平均先物と、名証上場の大型株のADRから当日の方向と先回り候補
- **決算カレンダー**：今後10営業日の名証上場銘柄の決算発表予定
- **要確認**の各銘柄に「Claudeに相談する文」（コピーボタン付き）
- **検証結果**：過去データで、材料ごとに翌日・2日後に上がった割合・平均・中央値・下位10%・最大の下落、何日持つのがよいか、TOBの2日目、名証上場のみ・名証単独のみ（[reports/backtest.md](reports/backtest.md)）
- **AIの結論**（最上部）：AIアナリストの「今夜の注文」（設定は下の「AIアナリストの設定」）
- **入賞確率シミュレーター**：今の資産と残りの売買回数から、10位ライン（729万円）を超える確率を戦略ごとに比べ、今夜の攻め方を表示
- **自己採点**：推奨（ルールの1位・S・A・AIの買い）の翌日の結果と的中率。1週間ごとに点数を少しだけ見直し
- 予測モデルは検証の結果「不採用」（[reports/model.md](reports/model.md)）

以下は夜の好材料の部分です。上から順に並んでいます。
1. **締切**：今夜の注文締切（翌営業日の朝7:59）
2. **取得できなかったもの**：データが取れなかったときに表示します（前回のデータを使っている場合もあります）
3. **TOBの大きな枠**：TOB・MBOの対象になった銘柄が出たときだけ表示します
4. **S → A → 要確認 → 参考 → 悪材料** の順に並べた候補
5. 15:30より前の開示（参考）、TOBトラッカー

各候補には、コード・会社名・名証単独か重複か・開示時刻・タイトル・開示PDFボタン・本日終値（＝今夜の約定見込み価格）・300万円で買える株数・株探リンクを表示します。

## TOB価格の書き込み（tob_prices.csv）
PDFは自動で読まないため、TOB価格はあなたが書き込みます。ページの「TOB価格を書き込む」ボタンから編集画面を開き、1行に「コード,TOB価格,メモ」を書いて保存（Commit changes）してください。

```
code,tob_price,memo
1439,2150,安江工務店
```

次回の実行から「TOB価格と終値の差（%）」を計算します。差が1%以下になると「売り時」と表示します。

## 保有管理（holdings.csv・cash.csv）
ページの「holdings.csv を編集」「cash.csv を編集」ボタンから書き込みます。

```
code,shares,buy_price,buy_date,memo
6999,1000,2002,2026-11-02,KOA
```
- 買った日は「注文した夜の日付」。朝0:00〜7:59に買ったときは時刻も書きます（例 `2026-11-04 06:30`）。今タームの残り購入枠の計算に使います。
- 売ったら、その行を消します（株数を減らすだけでもOK）。
- cash.csv の `cash` にコンテスト画面の現金残高を書きます。名証単独銘柄を一度でも買ったら `single_bought` を `yes` に（保有中の単独銘柄は自動で判定し、売った後も覚えています）。

表示するもの：評価額・損益・合計資産・昨年10位ライン（+429万円）との差・今タームの残り購入枠・単独銘柄の購入状況・「売り→買い」の入れ替え案。保有銘柄に悪材料・TOB価格到達・ストップ安が出たら最上部に赤い警告を出します。

## LINE通知の設定（スマホでできます）
送るのは「夜：S・A・要確認・保有警告があるときに1通。そのあと新しいS・A・保有警告が出たら追加で1通（同じ銘柄は1回だけ、1晩の追加は2通まで）」「朝：朝レポートの要約1回」「自動実行が失敗したとき」だけです。月180通に達したら送りません（無料プランは月200通）。

用語：**LINE公式アカウント**＝お店などが使う、メッセージを送れるLINEのアカウント。**Messaging API**＝プログラムからLINE公式アカウントでメッセージを送る仕組み。**チャネルアクセストークン**＝プログラムが「このアカウントとして送ってよい」と証明するための合言葉（他人に見せない）。**ユーザーID**＝送り先（あなた）を表すID。**GitHub Secrets**＝合言葉を、誰にも見えない形でGitHubに保管する場所。

※画面の名前や位置は変わることがあります（2026年11月時点の想定）。違っていたら教えてください。

1. **LINE公式アカウントを作る**
   ブラウザで https://entry.line.biz/start/jp/ を開き、「LINE公式アカウントをはじめる」→ LINEアカウントでログイン → アカウント名（例：名証スキャナー）・業種などを入力して作成します。料金プランは無料の「コミュニケーションプラン」のままでOKです。
2. **Messaging APIを使えるようにする**
   https://manager.line.biz/ を開き、作ったアカウントを選ぶ →「設定」→ 左のメニュー（スマホでは上のメニュー）の「Messaging API」→「Messaging APIを利用する」→ プロバイダー（入れ物の名前。例：自分の名前）を作成 → 同意して進みます。
3. **ユーザーIDとトークンを取る**
   https://developers.line.biz/console/ にLINEアカウントでログイン → 2.で作ったプロバイダー → 公式アカウントと同じ名前のチャネルを開きます。
   - 「チャネル基本設定」タブのいちばん下の **「あなたのユーザーID」**（Uで始まる長い文字）をコピー
   - 「Messaging API設定」タブのいちばん下の **「チャネルアクセストークン（長期）」** の「発行」を押してコピー
   - 同じタブにある**QRコード**をLINEで読み取って、公式アカウントを**友だち追加**します（追加しないと届きません）
4. **GitHub Secretsに入れる**
   https://github.com/vfzfpt5767-debug/meisho-scanner/settings/secrets/actions を開き、「New repository secret」を押して次の2つを登録します。
   - Name: `LINE_CHANNEL_ACCESS_TOKEN` ／ Secret: 3.のトークン
   - Name: `LINE_USER_ID` ／ Secret: 3.のユーザーID
5. **テスト**
   https://github.com/vfzfpt5767-debug/meisho-scanner/actions/workflows/line-test.yml を開き「Run workflow」→ 1〜2分でLINEに「テスト送信です」が届けば完了です。

## AIアナリストの設定（スマホでできます）
用語：**スケジュールされたタスク（ルーチン）**＝Claude Code が決まった時刻や合図で自動で動く仕組み。**APIトリガー**＝外（GitHub Actions）から「今動いて」と合図を送る入口。**トークン**＝その合図が本物だと証明する合言葉（他人に見せない）。

流れ（**夜に注文して寝る**運用）：
- **毎晩21:15（祝日・休日も）**：AIアナリストが定時で動き、その夜の最終的な「今夜の注文」をLINEで必ず1通送ります（買う物がなければ「今夜は見送り」）。祝日・休日でも、注文締切前のターム（例：11/2 16:30〜11/4 7:59）が開いていれば、そのタームの判断をします。
- **臨時起動**：スキャンで新しいS・A・要確認・保有警告が出ると、GitHub Actions がAIを起動します（1晩3回まで）。AIがすでに調べた銘柄では起動しません。AIの判断の取り込みやLINEの記録のあとのページ作り直しでも起動しません。
- AIは調べて `decisions/` に「今夜の注文」を書き、`claude/ai-decisions` ブランチに push します → GitHub Actions がLINEで注文の指示を送り、ページ最上部の「AIの結論」を更新します。
- **保有の自動記録は16:30〜23:30に届いた注文だけ**。それより後の指示は「【参考（起きていれば）】」としてLINEで送るだけで、holdings.csv と cash.csv には記録しません（GitHub Actions の待ち時間で数分遅れることがあるので、23:20以降の臨時起動は参考になることがあります）。
- **入力が古いとき**（スキャンが動いていなかったとき）：AIは自分でスキャンを頼み（`claude/scan-request` ブランチへの push → scan-request → scan）、最長10分ほど待ってから判断します。それでも古ければ、必ず「今夜は見送り」の判断を出します（LINEが1通届きます）。
- **22:30の確認**：その夜の判断が届いていなければ、AIをもう一度起動して、LINEで「21:15のAIの判断が届いていません」と1回知らせます（ai-watch）。
- 朝のAIの起動はしません（利用枠の節約）。ページの朝レポートは今までどおりです。

※ ブランチ名は `ai-decisions` ではなく `claude/ai-decisions` にしています。ルーチンは初期設定では `claude/` で始まるブランチにしか push できないためで、こうすると安全のための制限を外さずに済みます。
※ 画面の名前や位置は変わることがあります（2026年11月時点の想定）。違っていたら教えてください。

1. **ルーチンを作る**：ブラウザで https://claude.ai/code/routines を開き、新しいルーチンを作成します。
   - 名前：名証AIアナリスト
   - 指示（プロンプト）：下の「入口（本番）」をそのまま貼り付け。中身の指示は毎回 main の `ai/analyst_prompt.md` を読むので、そのファイルを直してもルーチンの貼り直しは不要です。
     ```
     最初に `git fetch origin main && git show origin/main:ai/analyst_prompt.md` を実行して、リポジトリ meisho-scanner の最新の指示書 ai/analyst_prompt.md を読み、その指示に従って最後まで実行してください。モード：本番。
     ```
   - リポジトリ：`vfzfpt5767-debug/meisho-scanner`
   - モデル：Sonnet
   - 環境：full-net（ネットにつながる環境。Web検索に必要）
   - ブランチへのpushの制限（Permissions）：初期設定のまま（変えない）
2. **夜の定時起動**：トリガーに「スケジュール」を追加し、**毎日 21:15（日本時間）**にします（祝日・土日も動かします）。
3. **APIトリガーを追加**：同じルーチンの編集画面で「Add another trigger」→「API」→「Generate token」。表示された **URL** と **トークン** をコピーします（トークンは一度しか表示されません。なくしたら作り直せば、前のものは無効になります）。
4. **GitHub Secretsに入れる**：https://github.com/vfzfpt5767-debug/meisho-scanner/settings/secrets/actions で「New repository secret」を2回。
   - Name: `ANALYST_FIRE_URL` ／ Secret: 3.のURL（`https://api.anthropic.com/v1/claude_code/routines/trig_…/fire`）
   - Name: `ANALYST_FIRE_TOKEN` ／ Secret: 3.のトークン
5. **テスト用のルーチン**：1.と同じ設定で、名前「名証AIアナリスト（テスト）」、トリガーなし（スケジュールもAPIも付けない）のルーチンをもう1つ作り、指示に「入口（テスト）」を貼ります。
     ```
     最初に `git fetch origin main && git show origin/main:ai/analyst_prompt.md` を実行して、リポジトリ meisho-scanner の最新の指示書 ai/analyst_prompt.md を読み、その指示に従って最後まで実行してください。モード：テストモード。
     ```
   このルーチンで「今すぐ実行（Run now）」を押すと、休業日や締切後でも、直近の営業日のデータで最後まで判断します。結果は `decisions/test/` に書かれ、LINEに「【テスト】AIの結論：…」が届きます。holdings.csv・cash.csv・ページの「AIの結論」は変わりません（LINEは1通使います）。
6. **本番の動作確認**：本番のルーチンで「今すぐ実行」を押すと、営業日なら判断が push され、LINEに「【AIの結論】…」が届き、ページ最上部に「AIの結論」が出ます（16:30〜23:30なら保有も自動記録されるので、試すだけならテスト用を使ってください）。営業日の昼（7:59〜15:30）は注文できるタームの外なので、「タームの外」と答えて終わるのが正しい動きです。

注意：
- ルーチンの実行は Claude の利用枠（サブスクリプションの使用量）を使います。調査は1回あたり最大8銘柄・1銘柄2〜3回の検索に抑えています。
- AIの注文どおりに注文した前提で、holdings.csv と cash.csv を自動で更新します。違う注文をした（または注文しなかった）ときは、LINEのボタンで直せます（下の「LINEのボタン・返信で記録する」）。ページから2つのファイルを直接直すこともできます。
- AIはTDnetのページやPDFを開きません（TDnetのrobots.txtが自動取得を拒否しているため）。会社のIRページや報道で確認します。

## LINEのボタン・返信で記録する（Phase 5）
AIの「今夜の注文」のLINEに、ボタン **［指示どおり注文した］［注文しなかった］［別の注文をした］** が付きます。注文画面と同じく「18単位（1,800株）」のように**単位**で書きます。
- ［指示どおり注文した］：自動記録のまま（23:30以降の「参考」の指示なら、ここで記録します）
- ［注文しなかった］：その注文の自動記録を取り消します
- ［別の注文をした］：自動記録を取り消し、返信を待ちます。「買い 4445 10単位」「売り 6999 全部」「買い 4445 1000株 1665円」のように返信すると、その内容で記録します（値段を書かなければ、その日の終値）
- 記録したら「記録しました：保有○○、現金○○円」と返事が来ます（1分ほどかかります）
- 「**残高**」と送ると、保有・現金・評価額・今タームの残り購入枠がすぐ返ってきます
- 「**ボタン**」と送ると、いちばん新しいAIの注文のボタンをもう一度出します

しくみ：LINE →（中継役）**Cloudflare Workers** → GitHub Actions（line-event）→ holdings.csv・cash.csv を直して main に保存 → LINEで返事。
中継役に Cloudflare Workers を選んだ理由：無料（1日10万回まで）で、LINEからの合図が本物か（署名）を確かめられるため。Google Apps Script は届いた合図の署名を確かめられないので使いませんでした。
「残高」と「受け付けました」の返事は返信メッセージなので無料（月の通数に数えません）。「記録しました」の返事は1通に数えます（月180通の上限の中）。

用語：**Webhook**＝LINEが「ボタンが押された」「メッセージが来た」をこちらのURLに知らせる仕組み。**中継役（Worker）**＝その知らせを受け取ってGitHubに渡す小さなプログラム。**チャネルシークレット**＝LINEからの知らせが本物か確かめる合言葉。**personal access token**＝中継役がGitHubに「記録して」と頼むための合言葉。

※画面の名前や位置は変わることがあります（2026年11月時点の想定）。違っていたら教えてください。Cloudflare の画面がスマホで使いにくいときは、ブラウザのメニューの「デスクトップ用Webサイトを表示」（PC版サイト）にしてください。

### 1. GitHub の合言葉（personal access token）を作る
1. ブラウザで https://github.com/settings/personal-access-tokens/new を開きます（GitHubにログイン）。
2. **Token name**：`meisho-line`
3. **Expiration**（期限）：「Custom」を選び、`2026-12-31` にします（コンテストの後まで）。
4. **Repository access**：「Only select repositories」→ `vfzfpt5767-debug/meisho-scanner` を選びます。
5. **Permissions** →「Repository permissions」→ **Contents** を「**Read and write**」にします（Metadata は自動で Read-only になります。ほかは触らない）。
6. いちばん下の「**Generate token**」→ もう一度確認画面で「Generate token」。
7. 表示された `github_pat_…` で始まる文字を**コピー**してメモアプリに一時的に貼っておきます（この画面を閉じると二度と見られません）。

### 2. LINE のチャネルシークレットをコピーする
1. https://developers.line.biz/console/ → 前に作ったプロバイダー → チャネル（公式アカウントと同じ名前）を開きます。
2. 「**チャネル基本設定**」タブの「**チャネルシークレット**」をコピーしてメモに貼ります。
3. 前に使った「チャネルアクセストークン（長期）」と「あなたのユーザーID」も、同じ画面（「Messaging API設定」タブと「チャネル基本設定」タブ）からコピーしておきます。

### 3. Cloudflare Workers（中継役）を作る
1. https://dash.cloudflare.com/sign-up を開き、メールアドレスとパスワードでアカウントを作ります（無料。届いたメールのリンクで確認）。
2. ダッシュボードの左のメニュー（スマホは左上の「≡」）から「**Workers & Pages**」（「Compute（Workers）」と書かれていることもあります）→「**作成**（Create）」。
3. 「**Hello World から始める**（Start with Hello World!）」→ 名前を `meisho-line` にして「**デプロイ**（Deploy）」。
4. 「**コードを編集**（Edit code）」を押し、左の `worker.js` の中身を全部消します。
   https://github.com/vfzfpt5767-debug/meisho-scanner/blob/main/worker/line-webhook.js を別のタブで開き、右上のコピーボタンで全文をコピーして貼り付け →「**デプロイ**（Deploy）」。
5. Worker の画面に戻り「**設定**（Settings）」→「**変数とシークレット**（Variables and Secrets）」→「**追加**（Add）」で、次の5つを入れます。上の4つは種類を「**シークレット**（Secret）」、最後は「**テキスト**（Text）」にします。
   | 名前 | 値 |
   |---|---|
   | `LINE_CHANNEL_SECRET` | 2.のチャネルシークレット |
   | `LINE_CHANNEL_ACCESS_TOKEN` | チャネルアクセストークン（長期） |
   | `LINE_USER_ID` | あなたのユーザーID（Uで始まる） |
   | `GITHUB_TOKEN` | 1.の `github_pat_…` |
   | `GITHUB_REPO` | `vfzfpt5767-debug/meisho-scanner` |
   入れ終わったら「**デプロイ**（Deploy）」または「保存」を押します。シークレットは保存すると見えなくなります（安全に保管されます）。

### 6. 定時起動（Cron Triggers）を設定する（2026-11-04 追加）

## 開示の中身を確かめるしくみ（会社のIRページ・人への確認）
名証の小さな会社の開示は、夜のうちは検索にもニュースにも出ないことが多く、TDnet は自動では開けません（robots.txt）。そこで2つのしくみを足しました。

**1. 会社のIRページを直接見る**
- `data/ir_pages.json`：名証上場の会社ごとのIRニュースのページ。会社のトップページは名証の上場会社検索の「会社ホームページ」から取り、そこからIRのページをたどって探しています。**各社の robots.txt で許可されたページだけ**を開きます。
- スキャンのたびに、S・A・要確認の候補（最大8件）について、その会社のIRページから同じ開示（タイトルが似ているもの）を探し、PDFの先頭をAIへの入力（`ir_check`）に入れます。見つかったら、AIは検索しなくても中身を確認できます。
- 例：名工建設（1869）の11/5の自己株式取得は、会社のIRページのPDFから「取得し得る株式の総数 134,000株（上限）、発行済株式（自己株式を除く）に対する割合 0.53%」が読めました。
- 一覧は毎週月曜に作り直します（Actions →「ir-pages」→「Run workflow」で手動でも）。うまく見つからない会社は `data/ir_sources.csv` に `code,home,ir_news` の形で書けば、それを優先します。

**2. 人に確認を頼む（LINE）**
- AIが中身を確認できずに見送った候補のうち、確かめられれば買う価値があるもの（特に名証単独・TOB・ストップ高・点数が高いもの）を、1晩2件まで、AIの結論のLINEと一緒に頼みます。
  「【確認のお願い】… PDF：（TDnetのPDFのURL） 知りたいこと：取得する株数の上限が発行済株式の何%か…」
- PDFを開いて、**「確認 1869 0.53%（11/6〜3/31）」**のように返信してください（確認待ちが1件だけなら「確認」とコードは省いても読めます）。人がブラウザでTDnetのPDFを読むのは問題ありません。
- 答えが届くと、その情報を入力に足して**AIをもう一度起動**します（1晩2回まで）。その判断は、**注文締切（翌営業日7:59）より前なら23:30以降でも保有に記録**します。TOB価格を答えたときは tob_prices.csv にも書きます。
- 分からなければ返信しなくて大丈夫です。

**あなたの作業**：Worker のコードを新しくしてください（「確認 1869 0.53%」のような返信を受け取れるようにしたため）。
https://github.com/vfzfpt5767-debug/meisho-scanner/blob/main/worker/line-webhook.js を全文コピー → Cloudflare →「Workers & Pages」→ `meisho-line2` →「コードを編集」→ 全部消して貼り付け →「デプロイ」。

## データの出どころ
| データ | 取得元 | 備考 |
|---|---|---|
| 適時開示の一覧 | やのしんWEB-API（TDnetの一覧を配信する非公式API） | TDnet本体は robots.txt で自動取得を拒否しているので、**PDF/XBRLは自動で読みません** |
| 名証の上場銘柄・単独/重複・売買単位 | 名証公式サイトの上場会社検索 | 1日1回取得 |
| 終値・最終気配 | 名証公式サイトの「日報」「株式相場表（速報）」PDF | コンテストは**最終気配**を使う（KOAで確認済み）。約定がない銘柄は「気配のみ」と表示 |
| 開示の中身（PDF・本文） | 各社のIRページ（名証の「会社ホームページ」からたどる） | 各社の robots.txt で許可されたページだけ。TDnet は自動では開かない |
| 予備の株価 | Yahoo Finance（yfinance） | 名証の相場表が取れないときだけ。東証にも上場している銘柄のみ |

アクセスは1回の実行で数回〜十数回にとどめ、間隔をあけて、結果は `data/cache/` に保存しています。
